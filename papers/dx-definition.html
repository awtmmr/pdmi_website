RESEARCH NOTE No.1

DXを定義する
変革を、デジタルで微分する

Mamoru Awata（粟田 守）　／　2026年10月

「DX」は便利な言葉です。けれど定義のないまま使われると、IT化やツール導入と区別がつかなくなります。本ノートでは、DXを関数の記法で定義し、判定できる形にしてみます。

変革を、関数として書く

変革（CX）の中身は、どこから出発し、どこを目指すかで決まります。つまり変革は、現状と目指す姿の関数として書けます。

CX = f ( as-is , to-be )

変革は、現状（as-is）と目指す姿（to-be）で決まる

目指す姿が描けていない変革は、関数の引数が欠けている状態です。出発点を正しく見ていない変革も同じです。

DXは、デジタルを変数に持つ変革

では、DXとは何か。デジタル（d）を変数として含む変革、と定義します。

DX = CX ( d )

ちなみに d(cx) = c·dx という語呂合わせは、意図したものです。

判定式その一：デジタルは、変革に効いているか

∂CX / ∂d ≠ 0

デジタルを動かしたとき、変革が実際に動くか

ツールを入れたのに、業務も組織も何も変わりません。よくある光景ですが、これは偏微分がゼロの状態です。そのデジタルは、変革に効いていません。

判定式その二：デジタル化とDXを分けるもの

∂²CX / ∂d ∂org ≠ 0

デジタルの効き目が、組織のありようによって変わるか

紙をPDFに、ハンコを電子承認に置き換えます。こうした「デジタル化」では、デジタルの効果は組織と無関係に決まります。DXはそうではありません。デジタルと組織が掛け合わさって初めて生まれる変化、つまり交差項がゼロでないことが、DXの条件です。

デジタルの効き目が組織と無関係なら、それはデジタル化。
組織とともに効き目が変わるなら、それがDX。

実務への含意

この定義から、私たちの方針が一つ導かれます。最初にDXの要否そのものを問い直すことです。∂CX/∂d がゼロに近いなら、デジタルは要りません。要らないものをなくすのが先で、デジタルは本当に必要になったときに使います。
